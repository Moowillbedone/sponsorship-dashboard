01 지표 정의 · 데이터 출처

화면의 모든 숫자에 대한 계산식·분모·제외조건입니다. 대시보드 각 지표 옆 i 아이콘과 동일한 내용이며, 새로 구축할 때 이 정의를 그대로 지키면 숫자가 재현됩니다.

지표 / 섹션정의 · 산출 기준

🔍 후원 재원 분석 — 그리퍼가 받은 젬은 어디서 왔나후원된 젬의 출처(결제 vs 광고) 추정젬은 출처가 섞이는 재화라 후원에 쓰인 젬의 정확한 출처 추적은 어렵습니다. 대신 전체 유저 적립의 경로별 금액 비율로 후원받은 젬(확정 후원액)의 출처를 추정합니다. 적립 출처 = 인앱결제(유료 충전)·광고미션(무료 적립)·수기지급(2025-12 QA 테스트 지급분 제외). ※ 건수는 광고가 16배 많지만 금액은 결제가 광고의 34배 — 후원 재원의 대부분이 결제 젬.

애드팝콘 SSP · 미디에이션 광고앱 내 광고 지면 수익 · 단위 USD($)SSP/미디에이션 = 앱의 배너·전면 등 광고 지면을 여러 광고 네트워크에 경매·중개해 얻는 수익. 순매체비=매체사(그립) 정산액(USD). 요청→응답→노출→클릭 퍼널. eCPM=노출 1,000회당 수익(단가 지표). 광고 파트너 콘솔 기준.
SSP 성과 지표Request · Response · Impression · CTR · eCPM · Fill RateSSP 미디에이션 지면의 광고 서빙 지표. 요청(광고 호출)→응답(채워짐)→노출(렌더)→클릭 퍼널에서 파생 계산합니다. Fill Rate=응답÷요청, CTR=클릭÷노출, eCPM=순매체비÷노출×1000, 노출률(렌더)=노출÷응답. ※ 오퍼월(SDK)·쿠팡은 참여·구매 전환 모델이라 이 지표 체계가 적용되지 않습니다.
애드팝콘 파트너스 · 쿠팡 광고유저가 쿠팡 광고로 구매 시 수수료 수익 · 2026-04말 시작 · 단위 원쿠팡 파트너스(CPS) = 유저가 앱 내 쿠팡 광고를 통해 실제 상품을 구매하면 발생하는 제휴 수수료. 순매체비=우리 최종 수익(client_commission, 거래액의 약 4%). 거래액(GMV)=구매금액-취소금액. 구매전환율=구매수/클릭수. 광고 파트너 콘솔 파트너 리포트 기준, 2026년 4월말 도입.
젬은 이렇게 흐릅니다구매 → 후원 → 현금화유저가 젬을 사거나(결제) 광고로 모아 → 그리퍼에게 후원 → 그리퍼가 환전. 회사 현금은 ①구매 시 들어오고 ③환전 시 나갑니다. ②후원은 젬이 유저→그리퍼로 옮겨갈 뿐 현금이 움직이지 않습니다.
손익계산서실현 현금 기준 · 인앱 수수료 15%회사 통장에 실제 오간 현금으로 계산합니다. 매출은 유저 판매가(1젬 약 1.43원, 1,000원=700젬) 기준, 비용은 판매자 환전 지급(액면 1원 − 수수료 10% = 0.9원/젬) 기준. 후원 단계는 현금이 안 움직여 계산에서 빠집니다. 젬의 액면가는 1원이지만 판매가는 그보다 비싼 프리미엄이라 그 차액이 마진이 됩니다.
손익 민감도 — 현금화율이 오르면?모든 시나리오 흑자 · 광고 제외 젬 사업 기준현금화율(그리퍼가 환전하는 비율)과 인앱 수수료율에 따른 젬 사업 순손익. 지금은 현금화율이 낮아 흑자폭이 크고, 100%까지 올라도 흑자입니다.
현금화(환전) 내역신청일 기준… · 동기화 …판매자가 환전(현금화) 신청한 내역을 신청일 기준으로 집계한 표입니다. 손익의 "환전 지급(비용)"이 여기서 발생합니다. 데이터를 새로 동기화한 뒤 이 표의 금액이 늘었다면 그만큼 그리퍼가 환전해 실현 순손익이 줄어든 것입니다(데이터 누락이 아님).
핵심 회계 원칙 — 이것만은 반드시 유지
  • 현금주의(cash basis). 후원받은 젬 자체는 비용이 아닙니다. 그리퍼가 환전(현금화)할 때만 비용으로 인식합니다.
  • 미환전 젬은 우발부채. 비용이 아니라 부채로 별도 표기합니다. 환전 문턱(1만 젬)·사업자 요건 때문에 상당수는 끝내 환전되지 않습니다.
  • 인앱 수수료 15%를 젬 판매 총매출에서 차감해 순수취를 구합니다. 스토어 정책이 바뀌면 APP_FEE 상수 하나만 고치면 전 화면에 반영됩니다.
  • 정산 수수료 10%. 환전 시 회사가 10%를 가져가고 그리퍼가 90%를 수령합니다. 실제 현금 유출은 90% 지급액입니다.
  • 광고는 부가수익으로 분리. 젬 사업 손익과 합산하지 말고 별도 표기해야 사업 구조가 왜곡되지 않습니다.

다크민트 계열. 모든 색은 :root 커스텀 프로퍼티로 정의되어 있어, 토큰만 바꾸면 전 화면 톤이 한 번에 바뀝니다. 컴포넌트에 직접 색상값을 쓰지 마세요.

타이포 스케일

  • 히어로 수치 34–44px / 800 — 화면당 1개만
  • 섹션 제목 17–20px / 700
  • KPI 값 22–26px / 700 · tabular-nums
  • 본문 13.5–15px / 400
  • 캡션·힌트 12px / --text-dim
  • 숫자는 전부 천단위 구분 + 1단위까지 정확히. 「약 17만젬」식 반올림 금지 — 어드민 값과 대조가 안 됩니다.

차트 규칙

  • Chart.js 기반. 전역 테마를 한 곳에서 지정하고 개별 차트에서 색을 덮어쓰지 않습니다.
  • 면적 차트는 세로 그라데이션(상단 색상 → 투명)
  • 격자선은 rgba(255,255,255,.05)로 극히 약하게
  • 이중축은 단위가 다를 때만. 같은 단위면 단일축
  • 일/주/월 토글은 동일 컴포넌트 재사용 (aggPeriod)
  • 계열 색 순서 고정: 민트 → 블루 → 바이올렛 → 앰버

레이아웃 원칙

  • 카드 --radius:18px, 반투명 배경 + 1px 경계
  • KPI는 auto-fit minmax() 그리드로 자동 줄바꿈
  • 탭 = 최상위 네비. 첫 탭은 항상 손익계산서(경영 지표 우선)
  • 표는 overflow-x:auto 컨테이너 안에 — 본문이 가로로 밀리지 않게

지표 정의 규율 권장 유지

  • 거의 모든 숫자에 i 툴팁으로 정의·출처·분모·제외조건을 붙였습니다.
  • 이 습관을 유지하면 "이 숫자 뭐예요?"라는 질문과 지표 해석 분쟁이 사라집니다.
  • 새 지표를 추가할 때 툴팁부터 쓰고 구현하는 순서를 권합니다.

스냅샷 스키마 규약

모든 데이터 파일은 동일한 4-키 계약을 따릅니다. 새 지표를 추가해도 이 형태를 유지하면 화면 코드를 거의 고치지 않아도 됩니다.

{
  "kpi":    { 합계·비율 등 요약값 },
  "daily":  [ { "date": "YYYY-MM-DD", ... } ],
  "by___":  [ { 분류축: 값, ... } ],
  "top___": [ { 상위 N개 랭킹 } ]
}

정합성 필수 — daily의 합은 반드시 kpi 총계와 일치해야 합니다. 어긋나면 화면에서 바로 티가 납니다.

설계상 주의점 실패 경험

  • 원본 개인정보를 저장하지 마세요. 집계 단계에서 잘라내고, 랭킹이 필요하면 표시용 식별자만 남깁니다.
  • 월 경계 병합 버그 — 월 단위로 잘라 병합하면 월이 바뀔 때 말일 데이터가 유실됩니다. 날짜 키 기준 최신 우선 병합으로 과거를 보존하세요.
  • 페이지네이션은 총건수 기준 오프셋 분할 + 동시요청 제한 + 지수 백오프 재시도.
  • 긴 기간 조회는 리포트마다 상한이 있어 구간을 쪼개 순차 수집해야 합니다.
  • 주 경계는 월요일 00시 ~ 일요일 24시(KST). 어드민 주간 랭킹과 같은 경계를 써야 값이 맞습니다.
  • 후원 젬은 총액(gross) 기준으로 집계해야 어드민 「후원 받은 젬」과 1단위까지 일치합니다.
보안 요구사항 — 새로 만들 때 반드시
  • 운영 자격증명을 서버에 상주시키지 마세요. 관리자 세션 토큰을 서버에 저장해두면, 그 서버가 곧 데이터 유출 경로가 됩니다.
  • 인증 검사는 fail-closed로. if (SECRET && 불일치) 거부 형태는 시크릿이 비면 검사 자체가 생략됩니다. if (불일치) 거부로 쓰세요.
  • 데이터 파일이 정적 자산이면 화면에 비밀번호를 걸어도 소용없습니다. JSON URL을 직접 부르면 그대로 열립니다. 인증은 반드시 엣지/서버에서 강제하세요.
  • 디버그 경로를 인증 검사보다 위에 두지 마세요.
  • 사내 대시보드는 비공개 저장소 + 접근 통제된 호스팅에 두세요.

✓ 이 파일에 없는 것

  • 실제 매출·손익·정산 금액 (전부 합성값)
  • 크리에이터·유저 실명, 식별번호 (전부 「데모크리에이터 NN」·「데모유저 NNN」)
  • 계정·비밀번호·API 토큰·세션 쿠키
  • 내부 API 주소·엔드포인트·인증 방식
  • 외부 통신 — fetch·XHR·CDN 요청 0건. 인터넷을 끊어도 완전히 동작합니다
  • 수집 스크립트 · 동기화 기능

▲ 실제 데이터로 교체할 때

  • 실제 값을 넣는 순간 이 파일은 대외비가 됩니다. 배포·공유 경로를 먼저 정하세요.
  • 크리에이터 실명 + 개인별 수익·정산액 + 개인/사업자 구분의 조합은 개인정보보호법 적용 대상입니다. 접근 권한을 반드시 제한하세요.
  • 공개 저장소·공개 URL에 올리지 마세요. noindex는 검색 노출만 막을 뿐 접근 차단이 아닙니다.
  • 랭킹 표시가 목적이면 실명 대신 표시용 식별자 사용을 권장합니다.
데모 데이터 정합성 — 합성값이지만 실제와 동일한 회계 관계를 만족하도록 생성했습니다. 정산 수수료 = 젬 × 10%, 환전액 = 젬 − 수수료, 일별 시계열 합 = KPI 총계, 노출 ≤ 응답 ≤ 요청, 주간 랭킹 합 = 후원 확정 젬, 인과분석 4개 버킷 합 = 전체 쌍. 25개 정합성 검사를 전부 통과했으므로, 화면이 계산식대로 동작하는지 그대로 검증하실 수 있습니다.
