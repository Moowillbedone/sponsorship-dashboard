# 후원하기 대시보드 · Gem Analytics

라이브 커머스 후원하기(젬) 기능의 유저·크리에이터·결제 활동 분석 대시보드.

> ## ⚠️ 이 저장소는 공개 웹사이트로 서빙하지 않습니다
>
> 과거 이 저장소는 정적 호스팅으로 **공개 배포**되어 있었고, 집계 데이터와 운영 문서가
> 인터넷에서 접근 가능한 상태였습니다. 현재는 배포에서 제외했습니다.
>
> - 배포 번들에는 `index.html`(공지 페이지)만 포함됩니다 — `.vercelignore` 참조
> - 실제 데이터 파일, 수집 스크립트, serverless 엔드포인트는 **저장소에서 제거**했습니다
> - **저장소 자체를 비공개(private)로 유지**해야 합니다. 커밋 이력에 과거 데이터가 남아 있습니다

## 대시보드 보기

`dashboard-local.html` 을 **더블클릭**하면 브라우저에서 바로 열립니다.

- 단일 파일 · 외부 통신 없음 · 인터넷 연결 불필요
- 포함된 수치와 이름은 **전부 합성(데모) 값**이며 실제 데이터가 아닙니다
- 화면 구조 · 계산 로직 · 디자인 시스템 참고용이며, `📄 인수인계` 탭에
  지표 정의 · 컬러 시스템 · 재구축 가이드 · 취급 주의사항이 정리되어 있습니다

## 화면 구성

| 탭 | 내용 |
|---|---|
| **손익계산서** | 실현 현금 기준 손익, 젬 흐름(구매→후원→환전), 민감도 매트릭스 |
| **광고 수익** | 오퍼월 / 미디에이션(SSP) / 제휴 커머스 성과 |
| **유저 젬** | 적립·사용·만료 흐름, 유형·경로 분포, 시간대 활동 |
| **크리에이터 젬** | 후원 추이, 주간 랭킹, 정산(환전) 내역 |
| **젬 결제** | 매출 추이, 스토어·번들별 판매 |
| **유저 인사이트** | 그룹별 활성도, 리텐션, 후원↔팔로우 인과 분석 |

## 데이터 구조

대시보드가 읽는 집계 스냅샷은 공통 계약을 따릅니다.

```
{ "kpi": {...}, "daily": [...], "by___": [...], "top___": [...] }
```

`daily` 합계는 반드시 `kpi` 총계와 일치해야 합니다.

## 회계 원칙

- **현금주의** — 후원받은 젬은 비용이 아니며, 크리에이터가 **환전할 때만** 비용 인식
- **미환전 젬** — 비용이 아닌 우발부채로 별도 표기
- **인앱 수수료** — `APP_FEE` 상수 한 곳에서 관리
- **광고 수익** — 젬 사업 손익과 합산하지 않고 부가수익으로 분리

## 데이터 갱신

수집 스크립트는 보안상 이 저장소에 포함하지 않습니다.
실제 데이터 연동이 필요하면 사내 표준 절차에 따라 별도로 구현하시기 바랍니다.

**구현 시 필수 요건**

- 운영 자격증명(관리자 세션 토큰 등)을 서버에 상주시키지 않을 것
- 인증 검사는 **fail-closed** 로 작성할 것
  (`if (SECRET && 불일치) 거부` 형태는 시크릿이 비면 검사가 생략됨)
- 데이터 파일이 정적 자산이면 화면 단 비밀번호는 무의미함 — 인증은 **엣지/서버**에서 강제
- 비공개 저장소 + 접근 통제된 호스팅에서만 운영할 것
